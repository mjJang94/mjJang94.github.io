## 왜 만들었는가

처음 방문한 대형 주차장에서 차를 찾지 못한 경험이 출발점이었습니다.

GPS는 실내에서 10~50m씩 어긋나고, 위치 앱마다 결과가 다르며, 지도를 열면 엉뚱한 방향을 가리키기도 합니다. 수동 메모는 기둥 번호를 정확히 읽기 어려울 때가 많고, 그마저도 매번 남기기는 번거롭습니다.

핵심 아이디어는 이렇습니다. **차에서 내리는 순간을 자동으로 포착하면, 그 순간의 위치와 사진과 메모를 남길 수 있습니다.** 블루투스 연결 해제 시점, 하차 신호(활동 전이), 기압 센서(층수 힌트)를 함께 보고 주차를 판정하도록 설계했습니다.

이후 차 찾기 화면에서는 사진을 1순위로, 나침반 방향과 거리를 보조 수단으로 제공합니다. 지도 렌더링 성능과 추가 권한을 감수하는 대신, **사진 한 장이 지도보다 정확할 수 있다**고 판단한 결과입니다.

## 사용법

### 첫 실행 — 온보딩

1. **권한 사전 고지** (Play 정책 요구사항): 앱을 닫아도 위치를 감지한다는 점을 먼저 안내합니다.
2. **필수 권한 요청**: 블루투스 / 위치(포그라운드 + 백그라운드) / 알림 / 활동 인식
3. **차량 오디오 기기 선택**: 페어링된 기기 목록에서 추천 표시를 참고해 사용자가 직접 고릅니다.

이 선택이 유일한 일회성 입력이며, 이후 동작은 모두 자동입니다.

### 주차 위치 기록 (자동)

1. **승차 후** 블루투스 오디오(핸즈프리·카오디오)가 연결되면 앱 내부의 `CarConnectionState`가 기기를 추적합니다.
2. **하차 시** 블루투스가 해제되고, 정확히 그 시점에 Foreground Service가 기동합니다.
3. **네 가지 신호를 수집합니다.**
   - 블루투스 ACL 해제 (감지 트리거)
   - 활동 전이 IN_VEHICLE → STILL/WALKING (신뢰도 보강)
   - GPS 좌표 및 accuracy (위치)
   - 기압 센서 상대 고도 (층수 힌트)
4. **기록을 생성합니다.** 수집된 신호 조합에 따라 `CONFIRMED` 또는 `PRESUMED` 신뢰도로 저장합니다.

### 늘 세우는 곳에서 조용히 (조용한 장소)

같은 자리(반경 120m)에 이번 기록을 포함해 3회 이상 주차한 곳이면, 주차 알림에 **여기선 그만 알리기** 액션이 붙습니다. 이 액션을 누르면 해당 좌표가 `quiet_zone`으로 등록되고, 이후 그 범위 안에서는 알림만 건너뜁니다.

- 기록·차 찾기·이력·무료주차 타이머는 그대로 동작합니다. 중단되는 것은 주차 확인 알림 하나뿐입니다.
- 이름은 사용자가 직접 붙입니다. INTERNET 권한이 없어 역지오코딩이 불가능하기 때문이며, 이름을 지정하지 않으면 등록 날짜로 표시합니다.
- 설정의 알림을 안 띄우는 곳 카드에서 이름 수정과 삭제가 가능합니다.

### 차 찾기 (수동)

**홈 화면**에는 현재 주차 카드가 노출되며, 사진 썸네일과 메모 한 줄, 경과 시간을 함께 보여줍니다.

**차 찾기 진입 시** 제공되는 기능은 다음과 같습니다.

1. **거리 고리**: 내 위치와 차의 위치를 레이더 형태로 배치해 이격 거리를 표시합니다.
2. **나침반**: 현재 위치에서 차 방향을 화살표로 표시합니다. 지자기 기준을 진북으로 보정하고 센서 신뢰도를 함께 노출합니다.
3. **사진 보기**: 주차 시점에 촬영한 사진을 크게 표시해 기둥과 표지판을 확인할 수 있습니다.
4. **메모 확인**: B3, P-14 같은 사용자 입력 텍스트를 노출합니다.
5. **지도 앱 열기**: `geo:` 인텐트로 카카오맵·네이버지도 등에 핀을 전달합니다.

### 주차 기록 편집

기록 상세 화면에서 사진 추가와 삭제, 메모 수정이 가능합니다. 미니맵에서 핀을 끌어 GPS 오차를 직접 보정할 수 있으며, 기기 공유 시트를 통해 위치와 사진을 함께 전달할 수도 있습니다.

### 차량 관리 (선택)

구독(₩3,300)으로 해금되는 영역입니다.

**케어 항목 추가**
- 타입: 정기점검 / 보험 / 과태료 / 기초 검사 / 사용자 정의
- 기한: 날짜 지정
- 반복: 단발 또는 N개월 주기
- 알림: D-30, D-7, D-1, 당일 중 선택

**차량 정보 저장**
- 차종, 번호판, 연료, 메모를 저장하며 모두 기기에만 보관하고 외부로 전송하지 않습니다.

**소모품 교체 주기** (구독)
- 엔진오일, 타이어, 브레이크 패드 등을 관리합니다.
- 주행거리(km)와 기간(개월)을 동시에 추적해 먼저 도달하는 쪽을 기준으로 판정합니다.
- 주유 기록에서 최신 주행거리를 자동으로 읽어 잔여 비율을 계산합니다.

**주유 기록** (구독)
- 주행거리, 주유량, 금액을 기록합니다.
- 전량 주유법으로 연비를 계산합니다. 가득 주유 두 번 사이의 주행거리를 그 사이 주유량으로 나누는 방식입니다.

**차량 서류함** (첫 한 장 무료, 이후 구독)
- 자동차등록증, 보험증서, 정기검사증 등을 사진으로 보관합니다.
- 촬영하거나 갤러리에서 선택하면 즉시 AES-256-GCM으로 암호화해 앱 내부 저장소에 보관합니다.
- 열람할 때마다 생체인증을 요구하며, 생체 수단이 없으면 기기 잠금으로 대체합니다. 화면을 벗어나면 다시 잠깁니다.
- 열람 중에는 `FLAG_SECURE`를 적용해 화면 캡처와 최근 앱 미리보기를 차단합니다. 이 플래그는 서류함 화면에만 적용합니다.
- 만료일은 표시만 합니다. 알림은 케어 허브가 이미 담당하고 있어 중복 발송을 피하기 위해서입니다.

### 백업 및 복원

**로컬 백업** (구독)
- 공유 저장소의 다운로드 폴더에 `.parkkeep` 파일로 저장합니다.
- 주차 기록, 사진, 메모, 음성, 차량 정보, 설정을 함께 담습니다.
- **차량 서류는 백업 대상에서 제외합니다.** 다운로드 폴더는 다른 앱과 사용자가 접근할 수 있는 영역이므로, 암호화해 보관하는 서류를 여기에 평문으로 내보내면 서류함의 보안 전제가 무너지기 때문입니다.

**복원**
- 다른 기기에서 `.parkkeep` 파일을 열어 가져옵니다.
- 기존 데이터 유지와 덮어쓰기 중 선택할 수 있도록 했습니다.


### 핵심 알고리즘

#### 1. 주차 감지 — 신뢰도 계층

| 신호 | 판정 | 신뢰도 |
|---|---|---|
| 블루투스 ACL 해제만 | PRESUMED | 낮음 (잠시 통화로 끊겼을 수 있음) |
| ACL 해제 + 하차 전이 | CONFIRMED | 높음 |
| 수동 기록 | MANUAL | 사용자 판단 |

하차 신호는 3분 윈도우로 보관하고, ACL 해제 시점에 이 윈도우를 조회해 신뢰도를 결정합니다. 저장소는 `DriveSignalStore`의 인메모리 구조이며 주행 세션 동안만 유효합니다.

#### 2. GPS 오차 축소 — 칼만 필터

Fused location provider는 수 초 간격으로 좌표를 내보내는데, 그 오차는 대체로 서로 독립적인 잡음입니다. 독립 잡음은 N회 측정을 평균하면 표준편차가 1/√N로 줄어든다는 성질을 이용했습니다.

```kotlin
// 1차원 칼만 필터 (위도, 경도 각각 독립 적용)
data class LocationSmootherState(
    val estimated: Double,        // 현재 추정값
    val variance: Double,         // 불확실도
)

fun update(
    state: LocationSmootherState,
    observation: Double,
    observationVariance: Double
): LocationSmootherState {
    // 이득 K — 관측이 정확할수록 새 값을 더 무겁게 반영
    val K = state.variance / (state.variance + observationVariance)
    val newEstimated = state.estimated + K * (observation - state.estimated)
    val newVariance = (1 - K) * state.variance
    return LocationSmootherState(newEstimated, newVariance.coerceAtLeast(4.0))
}
```

목표 정확도를 10m로 설정했고, 실내가 아닌 일반 환경에서는 대부분 7~8초 안에 도달했습니다.

#### 3. 사용자 손보정 — 미니맵 드래그

핀을 끌어 놓으면 `unprojectMeters()`로 화면 좌표를 위경도로 되돌립니다.

```kotlin
fun unprojectMeters(screenX: Float, screenY: Float): LatLng {
    val metersPerPx = metersPerPixel(zoom, bounds)
    val offsetMeters = OffsetMeters(
        north = (mapCenterPx.y - screenY) * metersPerPx,  // 화면 y축은 아래가 +
        east = (screenX - mapCenterPx.x) * metersPerPx
    )
    return myLocation.destination(offsetMeters)
}
```

한 번 손보정하면 `location_corrected` 플래그가 설정되고, 이후로는 위치 오차 경고를 표시하지 않습니다.

#### 4. 소모품 교체 주기 — 거리와 기간의 복합 판정

흔한 실수는 5,000km마다 또는 3개월마다 중 한쪽만 보는 것입니다. 주행량이 적은 차는 기간을 놓치고, 자주 타는 차는 거리를 놓칩니다.

```kotlin
fun consumableStatus(
    lastReplacedAt: LocalDate?,
    lastReplacedKm: Int?,
    intervalKm: Int?,
    intervalMonths: Int?,
    currentKm: Int
): ConsumableStatus {
    if (lastReplacedAt == null) return UNKNOWN

    val distanceDue = intervalKm?.let {
        currentKm - (lastReplacedKm ?: 0) >= it
    } ?: false

    val dateDue = intervalMonths?.let {
        LocalDate.now() >= lastReplacedAt.plusMonths(it.toLong())
    } ?: false

    return when {
        distanceDue || dateDue -> OVERDUE
        else -> OK(percentRemaining = ...)
    }
}
```

사용자에게는 반원 아크 형태의 `PkGauge` 컴포넌트로 시각화했습니다.

#### 5. 조용한 장소 — 반복 판정과 비대칭 기본값

기준을 집인지 여부가 아니라 **매번 같은 자리에 대는 곳인지**로 바꾼 것이 핵심입니다. 배경은 트러블슈팅 항목에 정리했습니다.

```kotlin
/** 오차가 반경보다 크면 같은 장소인지 판별할 수 없습니다. 그 경우 덮지 않은 것으로 봅니다. */
fun QuietZone.covers(location: ParkingLocation): Boolean =
    location.accuracyMeters <= radiusMeters &&
        distanceMeters(latitude, longitude, location.latitude, location.longitude) <= radiusMeters

fun isRepeatedSpot(
    location: ParkingLocation?,
    pastLocations: List<ParkingLocation>,      // 이번 기록은 제외하고 전달
    radiusMeters: Int = QuietZone.DEFAULT_RADIUS_METERS,  // 120m
    threshold: Int = QuietZone.REPEAT_THRESHOLD,          // 3
): Boolean {
    if (location == null || location.accuracyMeters > radiusMeters) return false
    val nearby = pastLocations.count { past ->
        past.accuracyMeters <= radiusMeters &&
            distanceMeters(location.latitude, location.longitude, past.latitude, past.longitude) <= radiusMeters
    }
    return nearby + 1 >= threshold   // 이번 주차를 포함해야 세 번째부터가 됩니다
}
```

**선택한 값과 근거**

| 값 | 선택 | 근거 |
|---|---|---|
| 반경 120m | 단지 또는 건물 하나 | 키우면 인접 상가까지 조용해지고, 줄이면 지하 진입 직전의 마지막 좌표가 범위 밖으로 밀려납니다 |
| 3회 | 이번 기록 포함 | 두 번은 우연일 수 있고, 세 번은 습관으로 볼 수 있습니다 |
| 판정 불가 시 | 알립니다 | 잘못 알리면 알림 하나를 지우면 되지만, 잘못 침묵하면 낯선 곳의 주차 기록이 통째로 남지 않습니다 |

거리 계산은 평면 근사(위도 110,574 m/도, 경도 111,320·cos(lat) m/도)를 사용했습니다. 수백 미터 범위에서는 구면 공식과 차이가 없고, Android API에 의존하지 않으므로 유닛 테스트로 검증할 수 있습니다.

#### 6. 서류 암호화 — AES-256-GCM 직접 구현

```kotlin
/** @return `[IV 길이][IV][암호문+태그]` 형식. 그대로 파일에 기록할 수 있습니다. */
fun seal(plain: ByteArray): ByteArray {
    val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        .apply { init(Cipher.ENCRYPT_MODE, key()) }
    val iv = cipher.iv
    val body = cipher.doFinal(plain)          // 스트림이 아니라 일괄 처리
    return ByteArray(1 + iv.size + body.size).also { out ->
        out[0] = iv.size.toByte()
        iv.copyInto(out, destinationOffset = 1)
        body.copyInto(out, destinationOffset = 1 + iv.size)
    }
}
```

- 키는 `AndroidKeyStore`에 보관한 AES-256 키 하나입니다. 앱 프로세스는 키 자체를 읽을 수 없고, 지원하는 기기에서는 TEE 밖으로 노출되지 않습니다.
- `doFinal` 한 번으로 처리합니다. `CipherInputStream`은 스트림이 끝까지 읽히지 않으면 GCM 인증 태그 검사를 건너뛰고, 구현에 따라 실패를 그대로 삼키기도 합니다. 서류 사진은 최대 수 MB 수준이라 일괄 처리가 더 안전하고 단순합니다.
- 복호화 실패는 `AEADBadTagException`으로 그대로 전파합니다. 조용히 빈 값을 반환하면 서류가 사라진 것처럼 보이기 때문입니다.
- 키에 `setUserAuthenticationRequired`는 적용하지 않았습니다. 인증은 화면 진입 시점에 받습니다. 근거는 제한 사항에 정리했습니다.

**마이그레이션 정책** (출시 전 기준)
- 파괴적 초기화를 허용했습니다.
- 아직 배포된 적이 없어 보호해야 할 사용자 데이터가 없기 때문입니다.
- 출시 이후부터는 수동 마이그레이션만 작성할 예정입니다.

## 제한 사항

### 의도적 설계 결정

**1. INTERNET 권한 없음**
- 서버 백엔드를 두지 않고 모든 데이터를 로컬에 저장합니다.
- 지도 타일을 받을 수 없어 사진, 나침반, 거리 고리로 대체했습니다.
- Play 결제는 앱이 직접 통신하지 않고 Play 스토어 앱 프로세스가 처리하므로, 앱 자체에는 INTERNET 권한이 필요하지 않습니다.

**2. GPS 정확도를 전제하지 않음**
- 실내 주차장에서 30~100m 오차는 정상 범위로 봅니다.
- 오차가 크면 사용자에게 명시합니다. 이 건물 근처, 위치가 많이 흐려요 같은 문구를 사용합니다.
- 지도 대신 현장 사진을 1순위로 배치했습니다.

**3. 차량 데이터 조회 불가**
- 블루투스는 A2DP/HEADSET 프로필만 사용하므로 VIN, 차종, 연비를 읽을 수 없습니다.
- 기기 이름으로 브랜드만 추정합니다 (`CarBrandGuess`).
- OBD-II 동글(ELM327) 연동은 향후 별도 과제로 남겨두었습니다.

**4. 기압 센서 신뢰도**
- 절대 고도는 신뢰하지 않고 상대 변화만 사용합니다.
- 공조 설비가 있는 건물은 실내 기압이 급변할 수 있어 결과는 층수 힌트 수준입니다.
- 실측에서 2~3개 층 정도의 오차가 관측되었으므로, 확정 정보가 아닌 참고 정보로 표시합니다.

**5. Doze 모드 대응**
- 정확한 알람(SCHEDULE_EXACT_ALARM)을 요청하되, 거부되면 부정확 알람으로 강등합니다.
- 강등된 경우 몇 분 늦을 수 있다는 점을 사용자에게 미리 알립니다.

**6. 서류함 — 막을 수 없는 것을 막는다고 적지 않기**
- **인증을 암호화 키에 묶지 않았습니다.** `setUserAuthenticationRequired(true)`가 더 강한 보호이지만, minSdk 26부터 최신 API까지 인증 유효시간과 키가드 구현이 제각각이라 키에 묶으면 잠금화면을 변경했다는 이유로 사용자가 자기 등록증을 열지 못하는 사고가 발생합니다. 이 기능에서는 그 위험이 도난 위험만큼 심각하다고 판단했습니다. 현실적인 위협인 타인이 폰을 집어 든 상황은 화면 단위 게이트로 차단되고, 기기 분실은 전체 디스크 암호화와 키스토어가 담당합니다.
- **갤러리에서 가져온 사진은 갤러리에 그대로 남습니다.** 앱이 제거할 수 없으므로 화면에 그대로 안내했습니다.
- 카메라 앱은 평문 JPEG만 반환하므로 캐시를 잠시 거칩니다. 암호화 직후 0으로 덮어쓰고 삭제하며, 촬영 중 앱이 종료되어 남은 파일은 다음 실행 시 정리합니다. 다만 플래시 저장장치의 물리적 삭제까지는 보장하지 않습니다.
- **다른 기기에서 백업을 복원하면 목록만 넘어오고 원본은 없습니다.** 이를 숨기지 않고 이 기기에 원본이 없다고 목록에 표시합니다. 키스토어 키가 초기화된 경우도 같은 판정으로 걸러집니다.

## 트러블슈팅

### 집이면 알림을 끄면 되지 않는가 — 절반만 맞았습니다

**요청**: 주차로 판정된 곳이 집이면 알림이 불필요하지 않은가.

**검토**: 기준을 집으로 잡으면 안 된다는 결론에 도달했습니다.

| 집의 형태 | 알림의 가치 |
|---|---|
| 마당 또는 전용 주차면 (항상 같은 자리) | 없습니다. 순수한 소음입니다 |
| 아파트 지하주차장 (자리가 매번 바뀜) | 가장 높습니다. B3 어디였는지 기억나지 않는 상황이 이 앱의 존재 이유입니다 |

국내 주거 환경에서는 후자가 다수이며, 좌표만으로는 둘을 구분할 수 없습니다. 집을 자동 판별해 일괄로 알림을 껐다면, 앱이 가장 필요한 순간에 침묵했을 것입니다.

**해결**: 기준을 매번 같은 자리에 대는 곳인지로 바꾸고, 최종 판단은 사용자에게 넘겼습니다.

- 등록 진입점은 주차 알림의 여기선 그만 알리기 액션 하나로 한정했습니다. 성가심을 끄는 버튼은 성가신 그 순간에 있어야 실제로 눌립니다. 설정 화면까지 찾아 들어가는 사용자는 많지 않습니다.
- 이 액션은 반복 장소(3회 이상)에서만 노출합니다. 처음 방문한 곳에서 노출하면 다시 갈 일 없는 장소가 목록에 쌓입니다.
- 알림 액션은 최대 3개까지 표시되므로, 반복 장소에서는 주차 아니에요 액션의 자리를 이 액션이 대체합니다. 세 번 이상 주차한 곳은 오탐 확률이 낮아 이쪽이 더 유용하다고 판단했습니다.

**교훈**: 자동화의 정답이 앱이 알아서 처리하는 것이 아닐 때가 있습니다. 좌표로 알 수 없는 것을 추측해서 끄면, 실패했을 때 사용자는 그 실패를 인지조차 하지 못합니다. 울리지 않은 알림은 보이지 않기 때문입니다.

### 백로그에 적어둔 `EncryptedFile`이 이미 지원 중단 상태였습니다

**계획**: 서류함을 `androidx.security-crypto`의 `EncryptedFile`과 BiometricPrompt로 구성할 예정이었습니다.

**실제**: Jetpack Security는 유지보수가 중단되고 deprecated 처리되었습니다. 이 라이브러리가 대신 처리해주는 일은 결국 키스토어 키로 AES-GCM을 수행하는 것 한 가지였습니다.

**해결**: 중단된 의존성을 안고 가는 대신 플랫폼 API로 직접 구현했습니다(`DocumentCrypto`). 그 과정에서 라이브러리가 가려주던 함정을 하나 발견했습니다.

> `CipherInputStream`은 스트림이 끝까지 읽히지 않으면 GCM 인증 태그 검사를 건너뛰며, 구현에 따라 실패를 조용히 삼키기도 합니다. 위변조 탐지가 목적인데 스트림을 쓰면 그 목적이 조건부로 사라집니다.

서류 사진은 최대 수 MB 수준이므로 `doFinal` 일괄 처리가 더 안전하고 단순합니다.

**교훈**: 백로그에 적어둔 라이브러리 이름은 결정이 아니라 그 시점의 가설입니다. 구현 시점에 다시 확인해야 합니다.

---

### `allowBackup="false"`면 백업에서 제외되는 줄 알았습니다

**상황**: 등록증과 보험증서는 백업 대상에서 제외해야 했습니다. 매니페스트에 `android:allowBackup="false"`가 이미 설정되어 있어 처리가 끝난 것으로 판단했습니다.

**실제**: 이 플래그는 클라우드 백업만 차단하고 기기 간 이전(D2D)은 차단하지 않습니다. 막아야 할 경로가 하나가 아니라 셋이었습니다.

| 경로 | 차단 위치 |
|---|---|
| 클라우드 백업 | `android:allowBackup="false"` |
| 기기 간 이전 | `data_extraction_rules.xml`의 `device-transfer` |
| 앱 자체 로컬 백업 파일 | `BackupRepository`에서 서류 디렉터리 제외 |

**부작용과 처리**: 다른 기기에서 복원하면 목록만 넘어오고 원본이 없습니다. 이를 숨기지 않고 이 기기에 원본이 없다고 목록에 표시했습니다. 이 판정은 키스토어 키가 초기화된 경우도 함께 걸러줍니다.

**교훈**: 백업 제외는 한 줄짜리 설정이 아니라 경로 목록입니다. 하나만 막으면 전부 막은 것으로 착각하게 됩니다.

### FGS 리시버가 브로드캐스트를 수신하지 못한다고 판단했던 문제

**초기 판단**: Android 8부터 매니페스트 등록으로는 암시적 브로드캐스트를 수신할 수 없으므로, FGS를 상시 유지해야만 수신이 가능하다고 생각했습니다.

**실제**: `ACTION_ACL_CONNECTED`와 `ACTION_ACL_DISCONNECTED`는 암시적 브로드캐스트 제한의 예외 목록에 포함되어 있습니다. 매니페스트 등록으로 수신할 수 있으며, FGS 백그라운드 시작 제한 역시 블루투스 브로드캐스트 수신을 예외로 두고 있습니다.

**해결**: FGS를 주행 세션 단위로 기동하고 종료하도록 변경했습니다. 배터리 소비와 사용자 경험이 함께 개선되었습니다.

**교훈**: 코드 주석에 적힌 불가능은 재검증이 필요합니다. Android 정책에는 예외가 많습니다.

### 차 찾기 화면에서 위치가 갑자기 튀는 문제

**원인 1**: `viewModelScope`에서 GPS를 구독해 화면이 꺼져도 수집이 계속되었습니다. 화면을 다시 켜면 수 분 전의 캐시 좌표가 먼저 도착해 화면에 반영되었습니다.

**원인 2**: fused provider가 내보낸 저품질 좌표를 무조건 수용했습니다. 10~20초마다 한두 번은 50m 떨어진 좌표가 유입되었습니다.

**해결 1**: `screenVisible` StateFlow로 화면 상태를 관리했습니다.

```kotlin
LifecycleResumeEffect(Unit) {
    observeLocation()
    onPauseOrDispose { stopObserving() }
}
```

**해결 2**: `settleCurrentLocation` 순수 함수로 좌표를 평가한 뒤 반영하도록 했습니다.

```kotlin
fun settleCurrentLocation(
    current: ParkingLocation?,
    candidate: ParkingLocation,
    now: Long
): ParkingLocation? {
    if (current == null) return candidate                     // 첫 값은 무조건 수용
    if (candidate.timestamp < now - 15_000) return null        // 15초 이상 지난 캐시
    if (current.accuracy <= candidate.accuracy * 1.5 + 5) return null  // 기존 값이 더 정확
    if ((candidate.latLng distance current.latLng) <= candidate.accuracy) return null  // 오차 범위 내
    return candidate
}
```

**결과**: 내부 테스트 기준으로 화면상의 위치 떨림이 눈에 띄게 줄었고, 지도 없이도 방향을 신뢰할 수 있는 수준이 되었습니다.

### 나침반의 북쪽 표시가 일부 기기에서 보이지 않는 문제

**원인**: 픽셀 단위로 그린 탓에 3배 밀도 기기에서 크기가 1/3로 축소되었습니다. 18px 반지름 핀이 6dp 상당으로 줄어들었고, 1배 밀도 기준의 프리뷰에서는 정상으로 보였습니다.

**해결**: `Density`를 이용해 dp 기준으로 변환했습니다.

```kotlin
drawCircle(
    color = Color.White,
    radius = 16.dp.toPx(),  // 모든 밀도에서 동일한 물리 크기
    center = Offset(centerX, centerY)
)
```

**교훈**: 밀도 독립 단위는 프리뷰만으로 검증할 수 없습니다. 여러 밀도의 실기기 확인이 필요합니다.

### 소모품 게이지가 원이 아니라 타원으로 보이는 문제

**원인**: Canvas 아크를 뷰 크기에 그대로 맞춰 그리다 보니, 가로로 긴 직사각형 영역에서는 아크가 납작한 반원으로 그려졌습니다.

**해결**: 아크가 항상 정사각형 영역 안에 그려지도록 수정했습니다.

```kotlin
val arcSize = size.minDimension
drawArc(
    color = color,
    startAngle = 180f,
    sweepAngle = 180f * percentage,
    useCenter = false,
    topLeft = Offset((size.width - arcSize) / 2f, 0f),
    size = Size(arcSize, arcSize),
    style = Stroke(strokeWidth, cap = StrokeCap.Round)
)
```

**결과**: 모든 화면 크기에서 정확한 반원으로 렌더링됩니다.

### 카카오맵에서 핀이 표시되지 않는 문제

**원인**: `geo:lat,lng?q=lat,lng(내 차)` 형식에서 카카오맵이 `q` 값을 검색어로 해석해, 내 차라는 텍스트를 검색하다 실패했습니다.

**시도한 조합**

| URI | 핀 표시 | 카카오맵 호환 |
|---|---|---|
| `geo:lat,lng` | 미표시 (이동만) | 정상 |
| `geo:lat,lng?q=lat,lng(내 차)` | 표시 | 검색 실패 |
| `geo:lat,lng?q=lat,lng` | 표시 | 정상 |

**최종 선택**: 라벨을 제거한 `geo:lat,lng?q=lat,lng`를 사용했습니다. 핀 표시와 네이버지도 호환성을 모두 확보할 수 있었습니다.

**교훈**: 지도 앱의 인텐트 처리 방식은 표준화되어 있지 않습니다. 실기기 검증 외에 확인할 방법이 없습니다.

### 무료주차 알람이 정시에 울리지 않는 문제 (Doze 모드)

**원인**: 배터리 절전 정책으로 AlarmManager의 정확 알람 권한이 거부된 상태였습니다.

**초기 접근**: 조용히 부정확 알람으로 강등했습니다. 사용자는 이를 알 수 없었습니다.

**개선**: 강등 사실을 사용자에게 명시하도록 변경했습니다.

```kotlin
if (alarmManager.canScheduleExactAlarms()) {
    alarmManager.setExactAndAllowWhileIdle(
        AlarmManager.RTC_WAKEUP, triggerAt, pendingIntent
    )
} else {
    alarmManager.setAndAllowWhileIdle(
        AlarmManager.RTC_WAKEUP, triggerAt, pendingIntent
    )
    showNotice("무료주차 알람이 몇 분 늦을 수 있어요")
}
```

**원칙**: 한계를 감추지 않고 그대로 노출합니다.

### 블루투스 기기 선택에서 추천이 부정확한 문제

**원인**: 기기 이름과 클래스만으로 추정해, 휴대용 핸즈프리 스피커도 차량으로 분류했습니다.

**해결**: 점수제를 도입했습니다 (`CarLikelihood.score()`).

```kotlin
fun score(device: BluetoothDevice): Int {
    var score = 0

    // 기기 클래스
    if (device.bluetoothClass?.majorDeviceClass == BluetoothClass.Device.Major.AUDIO_VIDEO) {
        score += 60
    }

    // 지원 프로파일
    if (device.uuids?.any { it.isCarAudio } == true) {
        score += 25
    }

    // 이름 단서
    if (device.name?.contains("Hyundai", ignoreCase = true) == true) score += 40
    if (device.name?.contains("Samsung", ignoreCase = true) == true) score += 30
    if (device.name?.contains("AirPods", ignoreCase = true) == true) score -= 60

    return score
}
```

- 45점 이상인 기기만 추천으로 표시합니다.
- 실제 기록 생성은 사용자가 선택한 MAC 주소가 완전히 일치할 때만 수행합니다.

### 유닛 테스트에서 한글 경로가 깨지는 문제

**원인**: Windows 환경에서 JVM의 `file.encoding` 기본값이 MS949로 잡히면서, Gradle 테스트 워커가 읽는 경로와 리소스의 인코딩이 어긋났습니다.

**해결**: `gradle.properties`에서 인코딩을 UTF-8로 고정했습니다.

```properties
org.gradle.jvmargs=-Dfile.encoding=UTF-8
kotlin.daemon.jvmargs=-Dfile.encoding=UTF-8
```

**교훈**: 빌드 환경의 기본 인코딩은 OS와 로케일에 따라 달라집니다. 팀 규모와 무관하게 프로젝트 차원에서 명시적으로 고정하는 편이 안전합니다.

### Room 마이그레이션과 파괴적 초기화 사이의 판단

**상황**: v1.0 출시 전이라 스키마를 자주 변경했습니다.

**초기 시도**: 매번 마이그레이션을 작성했으나, 보호할 사용자 데이터가 없는 시점이라 비용 대비 효용이 없었습니다.

**정책 결정**

```kotlin
@Database(
    entities = [...],
    version = 3,
    exportSchema = true   // 스키마 JSON은 남깁니다. 출시 후 마이그레이션의 출발점이 됩니다
)
abstract class ParkKeepDatabase : RoomDatabase() {
    companion object {
        fun buildDatabase(context: Context): ParkKeepDatabase =
            Room.databaseBuilder(context, ParkKeepDatabase::class.java, "parkkeep")
                .fallbackToDestructiveMigration()  // v1.0 출시 전까지만 유지
                .build()
    }
}
```

출시 이후에는 `fallbackToDestructiveMigration()`을 제거하고 모든 변경을 `Migration` 클래스로 명시할 계획입니다.

**교훈**: 출시 여부가 데이터의 가치를 결정합니다.

### Play 신규 앱 심사의 백그라운드 위치 사전 고지 요구사항

**요구사항**: 시스템 위치 권한 다이얼로그보다 먼저 앱이 직접 사전 고지를 해야 합니다.

**해결**: 온보딩 화면에 목적과 저장 범위를 명시했습니다.

```kotlin
Column {
    Text("위치 권한을 요청해요")
    Text(
        """
        앱을 닫아도 차를 감지하기 위해 위치를 기록합니다.
        기록한 정보는 기기에만 저장하고 외부로 보내지 않아요.
        """.trimIndent()
    )
    Button(onClick = ::requestLocationPermission) {
        Text("동의하고 계속")
    }
}
```

**핵심**: 앱이 닫혀 있거나 사용 중이 아닐 때도 수집한다는 사실을 완곡하게 돌리지 않고 그대로 기재했습니다.

## 최종 평가

### 배운 점

**1. 로컬 우선 설계**
권한 제약을 기능의 한계가 아니라 설계의 출발점으로 삼았습니다. INTERNET 권한 없이도 충분한 경험을 만들 수 있었고, 현장 사진이 지도보다 정확한 단서가 되는 경우가 있다는 것을 확인했습니다.

**2. 순수 함수의 가치**
MVI와 리듀서 분리를 통해 나침반 보정, 좌표 투영, 소모품 계산, 조용한 장소 판정을 모두 순수 함수로 검증할 수 있었습니다. 거리 계산도 평면 근사로 직접 구현해 Android API 의존을 끊었고, 그 덕분에 유닛 테스트로 덮을 수 있었습니다.

**3. 기기 다양성 대응**
에뮬레이터 검증에 의존하지 않고 유닛 테스트로 판정 로직의 품질을 유지했습니다. 다만 나침반 렌더링처럼 밀도와 센서에 의존하는 영역은 실기기 확인이 필수였습니다.

**4. 한계의 투명한 노출**
할 수 없는 것은 할 수 없다고 표시했습니다. 오차가 크면 이 건물 근처로, Doze로 지연되면 몇 분 늦을 수 있다고, 자기장이 교란되면 방향을 신뢰하지 말라고, 다른 기기에서 복원하면 원본이 없다고 각각 안내했습니다.

**5. 자동화하지 않는 판단**
좌표로 알 수 없는 것을 추측해서 기능을 끄면, 실패했을 때 사용자는 그 실패를 인지하지 못합니다. 울리지 않은 알림은 보이지 않기 때문입니다. 집이면 조용히라는 판단을 앱이 자체적으로 내리지 않고 알림 위의 명시적 버튼으로 물어본 이유입니다.

### 수치

- **유닛 테스트**: 225건 통과 (판정·계산 순수 함수 중심)
- **화면**: 11개 (온보딩 · 홈 · 주차 상세 · 차 찾기 · 이력 · 케어 허브 · 차량 정보 · 주유/연비 · 서류함 · 감지 진단 · 설정)
- **앱 외부 진입점**: 홈 위젯 · 앱 숏컷 2종 · 빠른 설정 타일 · 알림 4종
- **DB 스키마**: Room v3 (출시 전이므로 마이그레이션 없이 파괴적 초기화 적용)
- **버전**: `versionCode 105` / `1.0.5`
- **진행 상태**: 내부 테스트 트랙에서 결제 직전 구간까지 실기기 검증을 완료했습니다. 프로덕션 심사 서류(백그라운드 위치·FGS 타입·정확 알람 선언 및 시연 영상)는 준비를 마쳤고, 결제 기능으로 인한 통신판매업 신고 결과를 기다리는 중입니다.
