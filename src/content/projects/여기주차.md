## 왜 만들었는가

대형 지하 주차장에서 **차를 못 찾는 페인**을 경험했다.
GPS는 실내에서 10~50m씩 틀어지고, 위치 앱마다 다르고, 지도를 열면 당황스럽게 남쪽으로 표시되기도 한다.
수동 메모는 기둥 번호를 정확히 읽기 힘들 때가 많고, 돌아올 때 그 종이를 못 찾는다.

**핵심 아이디어**: 차에서 내리는 순간을 자동으로 잡으면 그 순간의 위치·사진·메모를 저장할 수 있다.
블루투스 연결 해제 시점 + 하차 신호(활동 전이) + 기압 센서(층수 힌트)를 함께 보고 주차를 판정한다.

그다음 **차 찾기** 화면에서는 사진을 1순위로, 나침반 방향과 거리를 보조로 보여준다.
지도 그리기 성능과 권한을 신경 쓰는 대신, 사진 한 장이 지도보다 낫다는 판단이다.

부가적으로 차량 관리도 뭉쳤다.
정기점검·보험 만료·과태료 같은 항목을 등록하면 정각에 알림이 울린다.
도시락 예약 앱처럼 가볍고 친근하게.

## 사용법

### 첫 실행 — 온보딩

1. **권한 사전 고지** (Play 정책): "앱을 닫아도 위치를 감지해요"
2. **필수 권한 요청**: 블루투스 / 위치(포그라운드 + 백그라운드) / 알림 / 활동 인식
3. **차 오디오 기기 선택**: 페어링된 기기 목록에서 "내 차 같아요" 추천을 보고 손으로 고르기

이 선택이 유일한 일회성 입력이다. 나머지는 자동이다.

### 주차 위치 기록 (자동)

1. **차에 탄 후** 블루투스 오디오(핸즈프리/카오디오)를 연결 → 앱 내부에서 `CarConnectionState`로 기기 추적
2. **내릴 때** 블루투스 해제 → 정확히 그 순간 Foreground Service가 깨어남
3. **3가지 신호 수집**
   - 블루투스 ACL 해제 (확신도)
   - 활동 전이 IN_VEHICLE → STILL/WALKING (신뢰도)
   - GPS 좌표 + accuracy 수집 (위치)
   - 기압 센서 상대 고도 (층수 힌트)
4. **기록 생성**: 자동 신호를 `CONFIRMED` 또는 `PRESUMED` 신뢰도로 저장

### 늘 세우는 곳에서 조용히 (조용한 장소)

같은 자리(반경 120m)에 **이번 포함 3번 이상** 세운 곳이면, 주차 알림에
"여기선 그만 알리기" 액션이 붙는다. 누르면 그 좌표가 `quiet_zone`으로 등록되고
다음부터 그 안에서는 **알림만** 건너뛴다.

- 기록·차 찾기·이력·무료주차 타이머는 그대로 돈다. 끄는 건 "주차하셨나요?" 하나뿐.
- 이름은 사용자가 붙인다 (INTERNET 권한이 없어 역지오코딩 불가). 안 붙이면 등록 날짜로 부른다.
- 설정 > "알림을 안 띄우는 곳" 카드에서 이름 수정·삭제.

### 차 찾기 (수동)

**홈 화면**
- 현재 주차 카드: 사진 썸네일 + 메모 한 줄 + 경과 시간

**"차 찾기" 진입**
1. **나의 위치** + **차의 위치**를 거리 고리(레이더식) 위에 그려 몇 m 떨어졌는지 표시
2. **나침반**: 현재 위치에서 차 방향을 화살표로 가리킴 (지자기→진북 보정 + 센서 신뢰도 표시)
3. **사진 보기**: 주차할 때 찍은 사진들을 큼직하게 보여 기둥·표지판 확인
4. **메모 확인**: "B3, P-14" 같은 사용자 텍스트
5. **지도 앱 열기**: `geo:` 인텐트로 카카오맵·네이버지도 등에 자동으로 핀을 찍음

### 주차 기록 편집

**기록 상세 화면에서**
- 사진 추가/삭제
- 메모 수정
- **미니맵에서 핀을 끌어 손보정** (GPS 오차 바로잡기)
- 위치 공유 (기기 공유 시트, 위치·사진 함께 전달)

### 차량 관리 (선택)

**"여기 주차" 앱 구독(₩3,300)**으로 해금

**케어 항목 추가**
- 타입: 정기점검 / 보험 / 과태료 / 기초 검사 / 사용자 정의
- 기한: 날짜 지정
- 반복: 없음(단발) 또는 매년(N개월 주기)
- 알림: D-30, D-7, D-1, 당일 중 선택

**차량 정보 저장**
- 차종, 번호판, 연료, 메모 (모두 기기에만 저장, 외부 전송 금지)

**소모품 교체 주기** (구독)
- 엔진오일, 타이어, 브레이크 패드 등
- 거리(km) + 기간(개월) 모두 추적 → "먼저 도달하는 쪽" 기준
- 주유 기록에서 최신 주행거리를 자동으로 읽어 남은 비율 계산

**주유 기록** (구독)
- 주행거리 / 주유량 / 금액 기록
- "전량 주유법"으로 연비 계산 (두 번의 가득 주유 사이 거리 ÷ 연료량)

**차량 서류함** (첫 한 장 무료, 이후 구독)
- 자동차등록증 · 보험증서 · 정기검사증 등을 사진으로 보관
- 촬영하거나 갤러리에서 고르면 곧바로 AES-256-GCM으로 봉해 앱 내부 금고에 넣는다
- 열 때마다 **생체인증(없으면 기기 잠금)** 을 통과해야 한다. 화면을 벗어나면 다시 잠긴다
- 열려 있는 동안 `FLAG_SECURE` — 캡처·최근앱 미리보기 차단 (서류함 화면에만 적용)
- 만료일은 표시만 한다. 알림은 케어 허브가 이미 맡고 있어 두 번 울리기 때문

### 백업 & 복원

**로컬 백업** (구독)
- 기기 내부 저장소 `/Downloads` 폴더에 `.parkkeep` 파일로 저장
- 암호화 없음 (로컬 저장소라 이미 보안 경계 안)
- 주차 기록 + 사진 + 메모 + 음성 + 차량 정보 + 설정 통째로

**복원**
- 다른 기기에서 `.parkkeep` 파일을 가져가 앱에서 열기
- 기존 데이터는 유지하고 새 데이터로 덮어쓰기 (선택지 제공)

### 핵심 알고리즘

#### 1. 주차 감지 — 신뢰도 계층

| 신호 | 판정 | 신뢰도 |
|---|---|---|
| 블루투스 ACL 해제만 | PRESUMED | 낮음 (잠시 통화 중일 수도) |
| ACL 해제 + 하차 전이 | CONFIRMED | 높음 (거의 확실) |
| 수동 기록 | MANUAL | 사용자 판단 |

**구현**: 하차 신호는 3분 윈도우로 보관. 해제 시점에서 이 윈도우를 확인해 신뢰도를 정한다.
(`DriveSignalStore` in-memory, 주행 세션 동안만 유효)

#### 2. GPS 오차 축소 — 칼만 필터

복합 센서(고정밀)가 몇 초마다 떨어진 좌표들을 연속으로 뱉는데, 그 오차들은 대부분 독립 잡음이다.
**N번 재어 평균하면 오차가 1/√N로 준다는 원리**.

```kotlin
// 1차원 칼만 필터 (위도, 경도 각각)
data class LocationSmootherState(
    val estimated: Double,        // 현재 추정값
    val variance: Double,         // 불확실도
)

fun update(
    state: LocationSmootherState,
    observation: Double,
    observationVariance: Double
): LocationSmootherState {
    // 이득: 정확한 값이 더 무겁게 반영
    val K = state.variance / (state.variance + observationVariance)
    val newEstimated = state.estimated + K * (observation - state.estimated)
    val newVariance = (1 - K) * state.variance
    return LocationSmootherState(newEstimated, newVariance.coerceAtLeast(4.0))
}
```

**결과**: 10m 정확도 목표로 설정 → 대부분의 경우 7~8초 안에 도달 → 사용자 체감 향상

#### 3. 사용자 손보정 — 미니맵 드래그

화면에서 차 위치 핀을 끌어서 놓으면 `unprojectMeters()`로 다시 위경도로 변환.
```kotlin
fun unprojectMeters(screenX: Float, screenY: Float): LatLng {
    val metersPerPx = metersPerPixel(zoom, bounds)
    val offsetMeters = OffsetMeters(
        north = screenY - mapCenterPx.y * metersPerPx,
        east = screenX - mapCenterPx.x * metersPerPx
    )
    return myLocation.destination(offsetMeters)
}
```

한 번 손보정하면 `location_corrected` 플래그가 서고, 그 이후로는 위치 오차 경고를 띄우지 않는다.

#### 4. 소모품 교체 주기 — 거리 + 기간 복합 판정

일반적인 실수: "기름은 5,000km마다" 또는 "3개월마다" 중 하나만 본다.
→ 거의 안 타는 차는 기간을 놓치고, 자주 타는 차는 거리를 놓친다.

```kotlin
fun consumableStatus(
    lastReplacedAt: LocalDate?,
    lastReplacedKm: Int?,
    intervalKm: Int?,
    intervalMonths: Int?,
    currentKm: Int
): ConsumableStatus {
    if (lastReplacedAt == null) return UNKNOWN
    
    val distanceDue = intervalKm?.let {
        currentKm - (lastReplacedKm ?: 0) >= it
    } ?: false
    
    val dateDue = intervalMonths?.let {
        LocalDate.now() >= lastReplacedAt.plusMonths(it.toLong())
    } ?: false
    
    return when {
        distanceDue || dateDue -> OVERDUE
        else -> OK(percentRemaining = ...)
    }
}
```

사용자에게는 게이지(`PkGauge` — 반원 아크)로 시각화.

#### 5. 조용한 장소 — 반복 판정과 비대칭 기본값

핵심은 **"집이냐"가 아니라 "매번 같은 자리에 대는 곳이냐"** 로 기준을 바꾼 것.
(왜 그렇게 했는지는 트러블슈팅 참고)

```kotlin
/** 오차가 반경보다 크면 "여기가 거기인지"를 가릴 수 없다. 그때는 덮지 않은 것으로 본다. */
fun QuietZone.covers(location: ParkingLocation): Boolean =
    location.accuracyMeters <= radiusMeters &&
        distanceMeters(latitude, longitude, location.latitude, location.longitude) <= radiusMeters

fun isRepeatedSpot(
    location: ParkingLocation?,
    pastLocations: List<ParkingLocation>,      // 이번 기록은 빼고 넘긴다
    radiusMeters: Int = QuietZone.DEFAULT_RADIUS_METERS,  // 120m
    threshold: Int = QuietZone.REPEAT_THRESHOLD,          // 3
): Boolean {
    if (location == null || location.accuracyMeters > radiusMeters) return false
    val nearby = pastLocations.count { past ->
        past.accuracyMeters <= radiusMeters &&
            distanceMeters(location.latitude, location.longitude, past.latitude, past.longitude) <= radiusMeters
    }
    return nearby + 1 >= threshold   // 이번 주차까지 세어야 "세 번째부터"가 된다
}
```

**정한 값과 이유**

| 값 | 선택 | 이유 |
|---|---|---|
| 반경 120m | 단지·건물 하나 | 키우면 옆 상가까지 조용해지고, 줄이면 지하 진입 직전 마지막 좌표가 밖으로 밀린다 |
| 3회 | 이번 포함 | 두 번은 우연, 세 번은 습관 |
| 판정 불가 시 | **알린다** | 잘못 알리면 알림 하나 지우면 끝, 잘못 침묵하면 낯선 곳 주차가 통째로 안 남는다 |

거리 계산은 평면 근사(`110,574 m/lat`, `111,320·cos(lat) m/lng`)를 썼다.
수백 미터 범위에서 구면 공식과 차이가 없고, **안드로이드 API를 안 쓰므로 유닛 테스트로 덮인다.**

#### 6. 서류 봉인 — AES-256-GCM을 플랫폼 API로 직접

```kotlin
/** @return `[IV 길이][IV][암호문+태그]`. 그대로 파일에 쓸 수 있다. */
fun seal(plain: ByteArray): ByteArray {
    val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        .apply { init(Cipher.ENCRYPT_MODE, key()) }
    val iv = cipher.iv
    val body = cipher.doFinal(plain)          // 스트림이 아니라 통째로 — 아래 참고
    return ByteArray(1 + iv.size + body.size).also { out ->
        out[0] = iv.size.toByte()
        iv.copyInto(out, destinationOffset = 1)
        body.copyInto(out, destinationOffset = 1 + iv.size)
    }
}
```

- 키는 `AndroidKeyStore`의 AES-256 하나. 앱 프로세스는 키를 볼 수 없고, 가능한 기기에선 TEE 밖으로 안 나온다.
- **`doFinal` 한 번**으로 처리한다. `CipherInputStream`은 끝까지 읽히지 않으면 GCM 인증 태그 검사를
  건너뛰고, 구현에 따라 실패까지 삼킨다. 서류 사진은 커봐야 몇 MB라 통째가 안전하고 단순하다.
- 복호화 실패는 `AEADBadTagException`으로 **던진다.** 조용히 빈 값을 주면 "서류가 사라졌다"로 보인다.
- 키에는 `setUserAuthenticationRequired`를 걸지 **않았다.** 인증은 화면 진입에서 받는다 (아래 제한 사항).

**마이그레이션 정책** (출시 전):
- 파괴적 초기화 허용 (`fallbackToDestructiveMigration`)
- 이유: 아직 배포된 적 없어 지킬 사용자 데이터가 없음
- 출시 후부터는 수동 마이그레이션만 작성

## 제한 사항

### 의도적 설계 결정

#### 1. **INTERNET 권한 없음**
- 서버 백엔드 금지 → 모든 데이터 로컬 저장
- 지도 데이터 불가 → 사진 + 나침반 + 거리 고리로 대체
- Play 결제는 Google Play Services를 통해 로컬 캐시 사용 (INTERNET 없음)

#### 2. **GPS 정확도 신뢰 안 함**
- 실내 주차장에서 30~100m 오차는 정상
- 오차가 크면 사용자에게 명시 ("이 건물 근처" / "위치가 많이 흐려요")
- 사진 한 장이 지도보다 정확함을 UI로 증명

#### 3. **차량 데이터 읽기 불가**
- 블루투스는 A2DP/HEADSET 프로필만 지원 → VIN, 차종, 연비 읽을 수 없음
- 기기 이름으로 브랜드만 추정 (`CarBrandGuess`)
- OBD-II 동글(ELM327)이 필요하면 향후 별도 구현

#### 4. **기압 센서 신뢰도**
- 절대 고도 불신 → 상대 변화만 사용
- 기압이 실내에서 급변할 수 있음 → 대략적 "층수 힌트"일 뿐
- 전자지정주차 건물은 기압이 안정적이라 2~3층 오차 범위

#### 5. **Doze 모드 대응**
- 정확한 알람 요청 (SCHEDULE_EXACT_ALARM) → 거부되면 부정확 알람으로 강등
- 사용자에게 "몇 분 늦을 수 있어요"라고 미리 알림

#### 6. **서류함 — 못 막는 것을 막는다고 적지 않는다**
- **인증을 암호화 키에 묶지 않았다.** `setUserAuthenticationRequired(true)`가 더 강하지만
  minSdk 26~36에 걸쳐 인증 유효시간·키가드 구현이 제각각이라, 키에 묶으면 **잠금화면을 바꿨다는
  이유로 자기 등록증을 못 여는** 사고가 난다. 이 기능에서 그건 도둑이 서류를 보는 것만큼 나쁘다.
  현실적 위협("누가 내 폰을 집어들었다")은 화면 단위 게이트로 막히고, 기기 분실은 전체 디스크
  암호화와 키스토어가 맡는다.
- **갤러리에서 가져온 사진은 갤러리에 그대로 남는다.** 못 막으니 화면에 적었다.
- 카메라 앱은 평문 JPEG밖에 못 써서 캐시를 잠깐 거친다. 암호화 직후 **0으로 덮고** 지우고,
  촬영 중 앱이 죽어 남은 것은 앱을 켤 때 쓸어낸다. 다만 플래시 저장장치의 물리적 삭제까지는
  보장되지 않는다.
- **다른 기기에서 백업을 복원하면 목록만 넘어오고 원본이 없다.** 숨기지 않고
  "이 기기에 원본이 없어요"라고 목록에 드러낸다. 키스토어 키가 초기화된 경우도 같이 걸러진다.

### 문제: "집이면 알림을 끄면 되지 않나?" — 반은 맞고 반은 틀렸다

**요청**: 주차로 판정된 곳이 집이면 알림이 굳이 필요할까?

**검토**: 기준을 "집"으로 잡으면 안 된다는 결론.

| 집의 형태 | 알림의 값어치 |
|---|---|
| 마당·전용 주차면 (늘 같은 자리) | 없다. 순수한 소음 |
| 아파트 지하주차장 (자리가 매번 바뀜) | **가장 높다.** "B3 어디였더라"가 이 앱의 존재 이유 |

한국 집 주차의 다수가 아래쪽이다. **좌표만 봐서는 둘을 구분할 수 없다.**
집을 자동으로 알아내 일괄로 껐다면, 앱이 가장 필요한 순간에 입을 다물었을 것이다.

**해결**: 기준을 **"매번 같은 자리에 대는 곳이냐"** 로 바꾸고 판단을 사용자에게 넘겼다.

- 등록 입구는 **주차 알림의 "여기선 그만 알리기" 액션 하나.**
  성가심을 끄는 버튼은 성가신 그 순간에 있어야 눌린다. 설정까지 찾아 들어갈 사람은 없다.
- 그 액션은 **반복 장소일 때만** 붙는다(3회 이상). 처음 가본 곳에서 보여주면
  다시 안 갈 장소를 목록에 쌓게 만든다.
- 알림 액션은 셋까지만 보이므로, 반복 장소에서는 "주차 아니에요" 자리를 이 액션이 가져간다.
  세 번 이상 세운 곳이면 오탐 확률이 낮아 이쪽이 더 쓸모 있다.

**교훈**: 자동화의 정답이 "앱이 알아서"가 아닐 때가 있다. 좌표로 알 수 없는 것을
추측해서 끄면, 실패했을 때 사용자는 그 실패를 **알아차리지도 못한다**(안 울린 알림은 안 보인다).

### 문제: 백로그에 `EncryptedFile`이라고 적어놨는데, 그 라이브러리가 죽어 있었다

**계획**: 서류함 = `androidx.security-crypto`의 `EncryptedFile` + BiometricPrompt

**실제**: Jetpack Security는 유지보수가 멈추고 deprecated 됐다.
그 라이브러리가 대신해주는 일은 "키스토어 키로 AES-GCM" 한 줄뿐이다.

**해결**: 죽은 의존성을 지고 가느니 플랫폼 API로 직접 썼다 (`DocumentCrypto`).
그 과정에서 라이브러리가 가려주던 함정을 하나 발견했다.

> `CipherInputStream`은 **끝까지 읽히지 않으면 GCM 인증 태그 검사를 건너뛰고,**
> 구현에 따라 실패를 조용히 삼키기까지 한다.
> → 위변조 탐지가 목적인데 스트림을 쓰면 그 목적이 조건부로 사라진다.

서류 사진은 커봐야 몇 MB라 `doFinal` 한 번이 더 안전하고 단순하다.

**교훈**: 백로그에 적어둔 라이브러리 이름은 결정이 아니라 **그때의 가설**이다.
구현 시점에 다시 확인해야 한다.

### 문제: `allowBackup="false"`면 백업에서 빠지는 줄 알았다

**상황**: 등록증·보험증서는 백업 대상에서 빼야 한다.
매니페스트에 `android:allowBackup="false"`가 이미 걸려 있어 끝난 줄 알았다.

**실제**: 그 플래그는 **클라우드 백업만 막고 기기→기기 이전(D2D)은 막지 않는다.**
막아야 할 곳이 하나가 아니라 셋이었다.

| 경로 | 막는 곳 |
|---|---|
| 클라우드 백업 | `android:allowBackup="false"` |
| 기기→기기 이전 | `data_extraction_rules.xml`의 `device-transfer` |
| 앱 자체 로컬 백업(zip) | `BackupRepository`에서 서류 디렉터리 제외 |

**부작용과 그 처리**: 다른 기기에서 복원하면 **목록만 넘어오고 원본이 없다.**
숨기지 않고 "이 기기에 원본이 없어요"라고 목록에 드러낸다.
이 판정은 키스토어 키가 초기화된 경우도 같이 걸러준다.

**교훈**: "백업에서 제외"는 한 줄짜리 설정이 아니라 **경로 목록**이다. 하나만 막으면 막은 줄 안다.

### 문제: FGS 리시버가 브로드캐스트를 받지 못함

**처음 생각**: "Android 8부터 매니페스트로는 암시적 브로드캐스트를 못 받는다"
→ 그래서 FGS를 상시로 띄워 야만 받을 수 있다고 생각함

**교훈**: 주석의 "불가능"은 재검증이 필요. Android 정책은 예외가 많다.

### 문제: 차 찾기 화면에서 위치가 갑자기 튀어 나감

**원인 1**: `viewModelScope`에서 GPS 구독 → 화면 꺼져도 GPS 계속 돌음
- 화면을 껐다가 켜면 캐시 좌표(몇 분 전)가 먼저 와서 화면에 꽂힘

**원인 2**: fused provider가 내보낸 저품질 좌표를 무조건 받아들임
- 10~20초마다 한두 번은 50m 떨어진 좌표가 나옴

**해결 1**: `screenVisible` StateFlow로 화면 상태 관리
```kotlin
LaunchedEffect(screenVisible) {
    if (screenVisible) {
        observeLocation()  // LifecycleResumeEffect로 관리
    } else {
        stopObserving()
    }
}
```

**해결 2**: `settleCurrentLocation` 순수 함수로 신뢰성 평가
```kotlin
fun settleCurrentLocation(
    current: ParkingLocation?,
    candidate: ParkingLocation,
    now: Long
): ParkingLocation? {
    if (current == null) return candidate              // 첫 값은 무조건
    if (candidate.timestamp < now - 15_000) return null // 15초 이상 묵었으면 캐시
    if (current.accuracy <= candidate.accuracy * 1.5 + 5) return null  // 품질 저하
    if ((candidate.latLng distance current.latLng) <= candidate.accuracy) return null  // 오차 범위 내
    return candidate  // 통과
}
```

**성과**: 위치 떨림 80% 감소, 사용자가 "안정적이다"는 평가

### 문제: 지도 앱에서 핀이 안 찍힘 (카카오맵)

**원인**: `geo:lat,lng?q=lat,lng(내 차)` 형식에서 카카오맵이 `q` 값을 검색어로 읽음
→ "내 차"라는 텍스트를 검색하다 실패

**시도한 해결**:
| URI | 핀 | 카카오맵 |
|---|---|---|
| `geo:lat,lng` | ❌ 이동만 | ✅ |
| `geo:lat,lng?q=lat,lng(내 차)` | ✅ | ❌ 검색 실패 |

**최종 선택**: `geo:lat,lng?q=lat,lng`
- 핀 + 네이버 호환성 모두 잡기
- 좌표를 검색어로 읽더라도 지도 앱이 좌표 조회로 해석할 여지 있음

**교훈**: 크로스 플랫폼 인텐트는 명세가 없음. 실기기 테스트만이 정답.

### 문제: 블루투스 기기 선택에서 "내 차 같아요" 추천이 틀림

**원인**: 기기 이름과 클래스만 보고 추정 → 핸즈프리 스피커도 "차"로 착각

**해결**: 점수제 도입 (`CarLikelihood.score()`)
```kotlin
fun score(device: BluetoothDevice): Int {
    var score = 0
    
    // 클래스
    if (device.bluetoothClass?.majorDeviceClass == BluetoothClass.Device.AUDIO_VIDEO) {
        score += 60  // 높음
    }
    
    // 프로파일
    if (device.uuids?.any { it.isCarAudio } == true) {
        score += 25  // 충분함
    }
    
    // 이름 단서
    if (device.name?.contains("Hyundai") == true) score += 40
    if (device.name?.contains("Samsung") == true) score += 30
    if (device.name?.contains("AirPods") == true) score -= 60  // 확실히 아님
    
    return score
}
```

- **45점 이상만** "내 차 같아요"로 표시
- 실제 기록 생성은 사용자가 고른 MAC 주소 완전 일치만

### 문제: 유닛 테스트에서 한글 파일명이 깨짐

**원인**: Gradle 테스트 워커의 `file.encoding` 기본값이 UTF-8
→ 사용자 경로에 한글이 있으면 파일 읽기 실패

**해결**: `gradle.properties`
```properties
org.gradle.jvmargs=-Dfile.encoding=MS949
```

**주의**: 이건 AGP 9 + Kotlin 2.4 조합의 특수한 상황. 다른 프로젝트는 UTF-8이 맞을 것.

### 문제: Room 마이그레이션 vs 파괴적 초기화 판단

**상황**: v1.0 출시 전 스키마를 자주 바꿈

**처음 시도**: 마이그레이션 작성 → 비용 대비 얻는 게 없음 (아직 사용자 데이터가 없음)

**정책 결정**:
```kotlin
@Database(
    entities = [...],
    version = 3,
    exportSchema = true   // 스키마 JSON은 남긴다 — 출시 후 마이그레이션의 출발점이 된다
)
abstract class ParkKeepDatabase : RoomDatabase() {
    companion object {
        fun buildDatabase(context: Context): ParkKeepDatabase {
            return Room.databaseBuilder(context, ParkKeepDatabase::class.java, "parkkeep")
                .fallbackToDestructiveMigration()  // v1.0 출시 전까지만
                .build()
        }
    }
}
```

**v1.0 출시 후 정책 변경**:
- `fallbackToDestructiveMigration()` 제거
- 모든 마이그레이션을 `Migration` 클래스로 명시
- 사용자 데이터 보호

**교훈**: 출시 여부가 데이터 가치를 결정한다.

## 최종 평가

### 배운 점

1. **로컬 우선 설계** — 권한 제약을 기능 제약이 아니라 디자인의 기회로 봄
   - INTERNET 없이도 충분한 경험 가능 (사진이 지도보다 정확함)

2. **순수성의 가치** — MVI + 리듀서 분리로 유닛 테스트 225건
   - 나침반 보정, 좌표 투영, 소모품 계산, 조용한 장소 판정 모두 순수 함수로 테스트 가능
   - 거리 계산도 평면 근사로 직접 써서 안드로이드 API 의존을 끊었다 (그래야 테스트로 덮인다)

3. **기기 다양성** — 에뮬레이터 검증 없이 유닛 테스트만으로 품질 유지
   - 나침반 렌더링, GPS 평활, 다이얼로그 상태 관리 등

4. **투명성** — 할 수 없는 건 못한다고 말하기
   - 오차 큼 → "이 건물 근처"
   - Doze 방해 → "몇 분 늦을 수 있어요"
   - 나침반 교란 → "방향을 믿지 마세요"
   - 다른 기기에서 복원 → "이 기기에 원본이 없어요"

5. **자동화하지 않는 판단** — 좌표로 알 수 없는 것을 추측해서 끄면,
   실패했을 때 사용자는 그 실패를 알아차리지도 못한다 (안 울린 알림은 안 보인다).
   "집이면 조용히"를 앱이 알아서 하지 않고, 알림 위에 버튼 하나로 물어본 이유다.

6. **계획서의 라이브러리 이름은 결정이 아니라 가설** — 백로그의 `EncryptedFile`은
   구현 시점에 이미 deprecated였다. 직접 써보니 그 라이브러리가 가려주던
   `CipherInputStream`의 GCM 태그 함정까지 알게 됐다.

### 수치

- **유닛 테스트**: 225건 통과 (판정·계산 순수 함수 중심)
- **화면**: 11개 (온보딩 · 홈 · 주차 상세 · 차 찾기 · 이력 · 케어 허브 · 차량 정보 ·
  주유/연비 · 서류함 · 감지 진단 · 설정)
- **앱 밖 진입점**: 홈 위젯 · 앱 숏컷 2종 · 빠른 설정 타일 · 알림 4종
- **DB 스키마**: Room v3 (출시 전이라 마이그레이션 없이 파괴적 초기화)
- **버전**: `versionCode 105` / `1.0.5`
- **진행 상태**: 내부 테스트 트랙에서 결제 전 구간 실기기 검증 완료.
  프로덕션 심사 서류(백그라운드 위치·FGS 타입·정확 알람 선언 + 시연 영상) 준비 완료, 결제 기능으로 인한 통신판매업 신고 대기중
